## 已交付

1. `POST /v1/generate`：沿用姜约定的 `{concept, model, prompt}`，返回 `{spec}`。
   服务端环境配置兼容 Chat Completions 的上游，密钥只发上游、不回前端；默认不调用模型。
2. 总超时默认 6500ms；全局每进程每分钟 20 次、最多 2 个并发，无 IP 计数；
   超时中止请求，客户端断开时取消上游。上游响应限 1 MiB，不跟随重定向，不透传上游错误正文。
3. OpenAPI、服务 README、docs/01 / 02 / 03 与根 README 已同步，未改共享数据契约或队友业务代码。
4. #21 数据确认：存 `mount().spec` 的纯 TemplateSpec 数组；复用 `ttk.custom.v1`，不存 RuntimeTemplate。
   生成器对占用 id 改名，页面拒绝内置 id，相同自定义 id 由调用方去重替换；服务端最后成功上传生效。
   草稿 `persist === false` 不落盘。现有数据层已满足，不新增存储 key 或第二套格式。

## 验证证据

`npm run api:smoke` 共 40 项：保留原有同步 30 项，新增 10 组 #19 / #21 验收。
新测试位于 `generate-smoke.js`，使用隔离临时库、随机端口和真实 HTTP 模拟上游，不用真实模型密钥。

- 请求字段 / 长度、缺配置、非法环境变量；三种上游响应格式与服务端密钥请求头。
- 非法 JSON / 模板、超大响应、500、429、重定向、总超时、限流与并发释放。
- 原生成器的实际 `fetchSpec → HTTP 代理 → 模拟上游`：成功编译挂载；
  非法公式 / 非法 JSON / 500 / 超时均在重试一次后回到 `ai:false` 草稿。
- 模型 spec 本地保存、刷新读回、导出 / 导入后仍可 DSL 编译，未启用同步时数据侧零请求。
- 模板快照上传与 `GET/PUT /templates` 共用存储，同 ID 新客户端读回、其他 ID 隔离，服务重启后仍保留。

这些证据只验证软件链路，**不证明真实模型的输出质量、耗时或供应商兼容性已经验收**。

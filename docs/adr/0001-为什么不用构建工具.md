# ADR 0001 · 为什么 v0 不用构建工具与 ES module

- 状态：已接受（M0 阶段）
- 决策日期：2026-11-06
- 决策者：付（后续如变更需全员评审）

## 背景

本项目要参加软件创新大赛，初赛提交的是 Beta 原型 + 演示视频；评审与答辩现场未必有网络或 Node 环境，
队员分属前端 / 算法 / 引擎 / 后端四种背景，需要极低的上手成本。

## 决策

v0 采用纯 HTML/CSS/JS + 传统 `<script src>` 标签，全局命名空间 `window.TTK`，无 npm 依赖、无打包器、无后端。
Node 只用于本地校验与 CI，不参与运行。

## 理由

1. **双击可运行**：`file://` 下 ES module 会被 CORS 拦截，传统 script 标签不会；演示零风险。
2. **人人能上手**：姜写模板、曹改引擎、秦换适配器，都不需要先配工具链。
3. **契约比工具链重要**：本项目的创新点在「任意概念 → 参数化沙盒」，不在前端工程化；先把 schema 和分层定稳。
4. **git 历史即创新证据**：代码短小直白，便于在计划书里说明本次大赛期间完成了什么。

## 代价

- 没有模块隔离，靠命名空间与加载顺序约定（已在 `docs/01` 明确，CI 会校验路径与引用）。
- 无法用 npm 生态与类型检查；用 `tools/verify.js` 补足自动化校验。
- 文件体积增长后需要手动管顺序。

## 何时重新评估

满足任一条件时，由付发起 ADR 讨论是否引入 Vite + TypeScript（保留 `file://` 可跑的构建产物作为演示包）：

- 源码文件超过约 25 个，或多人同时改动导致加载顺序冲突频繁；
- 需要接入体积较大的第三方库（多模态识别 SDK、图表库）；
- 后端与前端需要共享类型定义，JSON Schema 已不足以约束。

在此之前，**不要为了"看起来专业"引入工具链**。

# 接口契约（代码级）

> 与 `contracts/` 里的 JSON Schema 配套：JSON Schema 管**数据长什么样**，本文管**函数怎么调**。
> 所有模块都挂在全局 `window.TTK` 下（传统 script 标签，无 ES module、无打包）。

## 0. 全局命名空间与加载顺序

`index.html` 里的脚本顺序就是依赖顺序，新增模块必须按层追加，不能乱序：

```
TTK.math / TTK.Engine       ← src/core/engine.js
TTK.expr                    ← src/core/expr.js       (依赖 TTK.math)
TTK.dsl                     ← src/model/dsl.js       (依赖 TTK.expr)
TTK.generator               ← src/model/generator.js (概念识别与模板生成，依赖 TTK.dsl)
TTK.colors / TTK.Renderer   ← src/viz/render.js
TTK.templates               ← src/model/templates.js (依赖 TTK.colors)
TTK.data                    ← src/learning/data.js
TTK.createGraph             ← src/learning/graph.js  (依赖 engine + data 实例)
TTK.settings                ← src/ui/settings.js     (本机生成代理设置，依赖 TTK.data)
TTK.views                   ← src/ui/views.js        (四视图路由与精修视图)
TTK.engine / UI             ← src/ui/app.js          (最后一个加载)
```

## 1. 引擎（曹）· `src/core/engine.js`

```js
var engine = TTK.createEngine();          // 也可用 new TTK.Engine()
engine.register(runtimeTemplate);         // 必填 id/name/subject/params/compute，id 重复会抛错
engine.all(); engine.get(id); engine.unregister(id); engine.subjects();
engine.defaults(tpl)                     // -> { key: default, ... }
engine.select(id)                        // -> bool，重置参数为默认值并 recompute
engine.setParam(key, rawValue)           // -> bool，自动 clamp / 按 step 取整；无变化返回 false
engine.reset(); engine.recompute();
engine.findByQuery(text)                 // 关键词兜底；TTK.generator.recognize() 会包装它并标注来源
```

**事件**（`engine.on(evt, fn)`）：

| 事件 | payload |
|---|---|
| `change` | `state` — 任何重算后都触发，UI 唯一的数据源 |
| `select` | `state` — 切换概念 |
| `param` | `{ key, value, state }` |
| `reset` | `state` |

`state = { tpl, params, spec, revision, at }`，`spec` 即第 3 节的 `ComputeResult`。

**数学工具** `TTK.math`：`clamp / linspace / rng(seed) / gaussian(rand) / solve(A,b) / rk4(f,t,y,dt) / fmt(v,digits)`。
`rng` 是**可复现**的：拖参数时曲线不得随机抖动，模板里禁止直接用 `Math.random()`。

## 2. RuntimeTemplate（姜与曹的交界）

引擎只认这一个对象形状，DSL 编译产物与手写精修模板**必须统一**：

```js
{
  id, name, subject,                       // 必填
  icon, level, keywords, brief, concept,   // 可选：展示用
  prerequisites: ['gradient', ...],       // 可选：图谱边，填不存在 id 会被忽略
  custom: true, spec: { /* 原始 TemplateSpec */ },  // 可选：DSL 生成模板带
  params: [{ key, label, min, max, step, default, unit, hint }],
  compute: function (p, M) { return ComputeResult; },  // p=参数快照，M=TTK.math
  challenges: [{ text, check: function (p, m) { return boolean; } }]
}
```

`compute` 必须是**纯函数**：同样的 `p` 必须得到同样的结果，不碰 DOM / Canvas / localStorage / 网络。

## 3. ComputeResult（→ 付渲染）

```js
{
  chart: {
    panels: [{
      title, xLabel, yLabel,
      xDomain: [min, max], yDomain: [min, max],     // 可省，渲染器自动推断
      series: [{ name, color, points: [[x, y], ...], style: 'line|dashed|area|scatter|bar', width, fill }],
      markers: [{ x, y, label, color }],            // 可省
      guides:  [{ axis: 'x'|'y', value, label, color }],
      bands:   [{ axis: 'x'|'y', from, to, color, label }]
    }]
  },
  metrics: [{ label, value, unit, digits, tone: 'good|warn|bad|plain', hint }],
  insight: '当前参数下的一句话洞察',
  m: { /* 任意中间量，供 challenges.check 与诊断使用 */ }
}
```

- `chart.panels` 可省（等价单面板）；点多面板由 `TTK.Renderer` 统一布局。
- `points` 里出现 `NaN / Infinity / null` 的坐标会被渲染器跳过，但 **CI 会判为失败**，模板方要保证数值稳定。
- `metrics[].value` 是**有限数**或简短**状态词**（如「已收敛」/「发散」）；`tone` 只影响配色，不影响逻辑。
- `m` 是模板与 `check()` 的私有通道，指标卡通过 `metrics` 展示，**不要把展示文案塞进 m**。

数据形状以 `contracts/compute-result.schema.json` 为准，最小样例是 `contracts/examples/compute-result.json`；
零依赖的形状校验器是 `TTK.dsl.validateResult(result) -> { ok, errors[] }`，CI 用它检查样例、全部模板输出与模拟帧。

> **#I9 模拟帧不扩展本契约**：播放帧只是把同一份 `chart / metrics / insight / m` 按步数截断后的视图，
> 不新增字段、不改含义，所以仍是 v1，渲染器与指标卡一行都不用改。播放进度从 `TTK.sim.state()` 读取，
> 不写进 ComputeResult，避免把运行时状态混进纯数据契约。详见第 9 节。

渲染侧只有一个入口：`new TTK.Renderer(canvasEl).draw(spec.chart)`。新增概念不应修改渲染器。

## 4. 模板 DSL（姜产出 → 曹编译）· `src/model/dsl.js`

```js
TTK.dsl.validate(spec, existingIds)  // -> { ok, errors[], fns, samples }
TTK.dsl.compile(spec, v?)            // -> RuntimeTemplate，可直接 engine.register()
TTK.dsl.prompt(conceptText)          // -> 给 LLM 的系统提示，要求只输出 TemplateSpec JSON
TTK.dsl.draft(text)                  // -> 本地降级草稿（不假装是 AI 生成）
TTK.dsl.blank() / TTK.dsl.example    // 模板工坊的初始内容
```

公式字符串由 `src/core/expr.js` 求值：`TTK.expr.validate(src) / eval(src, scope) / scope(p, M)`。
作用域只暴露 `x`（横轴）、`p.<key>`（参数）、`m.v0..v4`（指标）、`M`（TTK.math）、`Math`（白名单函数）、`PI / E`。

> ✅ **#I8 已收紧（PR #16）**：标识符路径只允许「根 + 一层属性」，`Math` / `M` 成员走固定函数白名单，
> 参数对象上的方法不可调用；作用域不暴露宿主 `Math`，属性读取只认自有属性，原型链不可达。
> 编译期拒绝除零、字面量/常量折叠溢出、深嵌套、超长表达式与白名单外标识符；运行时结果非有限则抛错。
> 幂右结合、一元负号优先级低于幂（`-2^2 = -4`）。安全断言见 `tools/verify.js` 第 8b 节。

**禁止**：赋值、语句、字符串、下标、对象字面量、函数定义、任何全局访问（含 `window`、`constructor`、`__proto__`）。校验在编译前完成，运行时不执行 JS。

## 5. 数据层（秦）· `src/learning/data.js`

所有读写必须经过 `TTK.data`，**上层不许直接碰 localStorage**：

```js
TTK.data.trail() / progress() / stuck() / custom() / saveCustom(list)
TTK.data.log(event)           // 写事件的唯一入口：补全字段 → 截断 300 → 落盘 → remote.push
TTK.data.markChallenge(id, i) // -> bool，首次完成 true，重复 false
TTK.data.addStuck(id)         // -> 当前卡点条数（上限 200）
TTK.data.byTpl(id, tpl)       // -> { interactions, stuck, challengeDone, challengeTotal, challengeRate }
TTK.data.stats(engine)        // -> 学习报告聚合
TTK.data.timeline(n)          // -> 最近 n 条（倒序）
TTK.data.exportAll(engine)    // -> LearningTrace JSON 字符串（匿名）
TTK.data.importAll(text)      // -> { ok, events } | { ok:false, error }
TTK.data.subscribe(fn) / clear()
TTK.data.migrate()            // -> { sources, normalized, kept }，幂等；模块加载时自动跑一次
TTK.data.lastMigration        // 首次自动迁移的报告，便于排查旧数据
TTK.data.remote.configure(url) // url 为空 => 本地模式；非空 => REST 模式
TTK.data.remote.push(event)    // 离线排队，联网批量 POST 到 <url>/events
TTK.data.remote.flush()        // -> Promise<{ok, events?, error?}>；上传后读回 /trace
TTK.data.remote.pending()      // 待上传事件数（不含进度 / 模板快照）
TTK.data.remote.identity()     // -> 本机随机匿名 ID，16 位十六进制
TTK.data.remote.identity(id)   // -> {ok, anonId? , error?}；手动恢复，缓存与队列按身份隔离
TTK.data.remote.lastError      // 最近一次同步失败原因；4xx 不丢弃队列
TTK.data.remote.storageError   // 非空表示持久化不可用，只能保留本次会话数据
TTK.data.read(key, fallback) / write(key, value, silent)  // 适配器原语；silent = 不通知订阅者
```

**自定义模板（#I3 / #21 共用一份格式）**：`ttk.custom.v1` 存纯 `TemplateSpec` 数组（可 JSON 序列化、
不含函数），工坊保存与模型生成都写这里，不另做第二套 key。模型模板带 `source: 'llm'`，
`dsl.validate` 允许该额外字段；本地草稿 `source: 'local-draft'` 不落盘。
`exportAll()` 把它放进 `customTemplates`（符合 `learning-trace.schema.json`），`importAll()` 写回后
由 `TTK.views.importReport()` 立即调 `TTK.app.restoreCustom()` 挂回引擎。
`saveCustom()` 会触发 `remote.changed()`，配置同步服务时随 `/trace/import` 的 snapshot 上传；
未配置时纯本地、零网络请求。生成代理的本机设置见 7b 节，它不进学习数据。

**秦确认（#21，11-08）**：数据层无需新增格式或 key。生成器遇到已占用 id 会改名，页面保存入口拒绝
内置 id；自定义 id 由调用方先去重再替换，服务端同 id 最后一次成功上传生效。`saveCustom()` 的入参是
`mount().spec` 这样的纯数据数组，不是 `mount().tpl`（后者含函数）。新增真实 HTTP 验收覆盖保存、刷新、
导出导入、`GET/PUT /templates` 与快照互通、同 ID 新客户端读回和重启保留；模型上游为本机模拟。

**换后端只需替换适配器**：`services/api/openapi.yaml` 定义了 `/events`、`/trace` 等端点；字段名与 `contracts/learning-trace.schema.json` 一致。上层（图谱 / 报告 / 工坊）一行都不用改。

**REST 模式仍同步读取本地缓存**，不把 getter 改成 Promise。`configure(url)` 后后台执行
`/events` 批量上传 → `/trace/import` 合并进度 / 卡点 / 自定义模板 → `GET /trace` 更新缓存，
缓存更新会触发 `subscribe(fn)`；需要即时重绘的视图可消费该通知。手动 `flush()` 可等待本轮同步。
无实时推送 / 定时轮询；在另一台设备操作后，通过 `flush()` 或刷新页面拉取。

待上传队列按服务地址与匿名 ID 分开落盘，不因刷新或 HTTP 错误而丢弃。5xx / 429 / 408 / 网络异常
按 1–30 秒退避重试，恢复联网立即重试；其他 4xx 保留数据并通过 `lastError` 报告，修复后手动 `flush()`。
挑战完成值取 OR，事件和卡点去重；同 id 模板以最后一次成功上传为准，不提供远端删除。
`clear()` 清空本机记录、取消待上传项并关闭同步，远端历史保留；已经送达服务端的请求无法撤回。
未配置 URL 时不建立队列、不生成匿名 ID、不发送网络请求，保持双击运行。

> ✅ **#I13 已完成**：`src/ui/app.js` 不再直接读写本地存储，也不再自带 `save()` / `trail` 内存缓存；
> 轨迹、挑战、卡点全部走 `TTK.data`，卡点推荐走 `graph.recommend()`。
> `TTK.data.migrate()` 在模块加载时幂等接管早期无版本后缀的键，**只写 v1、不删旧键**，旧轨迹不丢失。
> 数据层的 getter 会顺带规范化脏数据，字段与 `learning-trace.schema.json` 保持一致。

## 7. 四视图路由（付）· `src/ui/views.js`

四视图已由 #I1 接入，并由 #I2 / #I3 / #I14 精修。`index.html` 里 `#viewNav` 是导航条，`#view-<id>`
是四个容器，同一时刻只有一个不 `hidden`；沙盒三栏的 DOM 结构保持不变，所以拖参数 / 指标 / 挑战判定的链路完全没动。

```js
TTK.views.routes()            // -> [{ id, name, hash, mount, todo }, ...]，固定 4 条
TTK.views.register(id, fn)    // 注册挂载函数；渲染时只改自己的容器
TTK.views.mount(id)           // -> bool，未知 / 未注册返回 false
TTK.views.go(id, tpl)         // 切视图并写 hash；tpl 可省
TTK.views.setTpl(id)          // 应用层切概念时调用：保留当前视图，只换后半段
TTK.views.start()             // 应用层 init 末尾调一次：绑定 hashchange，返回初始 { view, tpl }
TTK.views.current()           // -> 当前 route 或 null
TTK.views.parseHash()         // -> { view, tpl }
TTK.views.hash()              // -> 当前应有的 hash 字符串
TTK.views.on(fn)              // fn(evt, payload)；'change' 的 payload = { route, tpl, hash }
TTK.views.refresh()           // #I14 / #I15：重绘当前视图（订阅 TTK.data 后数据一变就调用）
TTK.views.exportReport()      // #I2：返回匿名 LearningTrace v1 文本；字段白名单不通过时返回 null 且阻止下载
TTK.views.importReport(text)  // #I2：校验 schema + events 后交给 TTK.data.importAll，返回 bool
```

视图层订阅 `TTK.data.subscribe`，工坊编辑态 / 报告导出文本放在模块变量里，重绘不会丢输入；
模块被重新载入时先解绑 `window.__ttkViewsDataUnsub`，避免重复重绘。
`app.js` 另监听 `engine.on('register' / 'unregister')`，注册或卸载模板后侧栏与图谱节点数即时同步。
视图层不使用 `eval` / `new Function` / `fetch`，工坊编译一律走 `TTK.dsl.validate` → `TTK.dsl.compile` → `engine.register`。

**hash 格式 `#<view>/<tplId>`**（例：`#report/overfit`）：前半段决定视图，后半段记住当前概念；
v0 的 `#overfit` 这类只有模板 id 的链接会兼容回沙盒。`go()` / `setTpl()` 同步应用一次，
并用 `lastApplied` 去重浏览器随后派发的 `hashchange`，不会循环。
隐藏期间 `app.js` 跳过 Canvas 绘制，切回沙盒时由 `change` 事件补一次重绘（渲染器每次重读画布尺寸）。

### 7a. 概念输入与模板生成（姜）· `src/model/generator.js`

```js
TTK.generator.configure({ endpoint, model, transport }) // -> {enabled, endpoint, model}；endpoint 为空 = 本地模式
TTK.generator.config()                                   // -> 公开配置，不含任何密钥
TTK.generator.recognize(input)                           // -> {ok, conceptId, concept, source, level, unsupported, message}
                                                         // level: supported 文字 / fallback 文件名或图片内文字 / unsupported 纯语音或无可读文字
TTK.generator.generate(concept, { ids })                 // 本地模式：同步返回 {ok, spec, source:'local-draft', ai:false, reason, attempts}
                                                         // 配置代理：返回 Promise，成功 {ai:true, source:'llm', spec}
TTK.generator.mount(engine, spec)                        // -> {ok, tpl, source, spec, persist} | {ok:false, errors[]}；唯一进引擎的入口
                                                         // spec 为去函数、可 JSON 序列化的模板；persist 仅 source==='llm' 时为 true（PR #22）
```

- **安全**：模型输出永远只当数据。先 JSON 化去函数，再 `dsl.validate` → `dsl.compile`（公式只走 `expr` 白名单）→ `engine.register`；`apiKey` / `token` 字段一律不接受，客户端不带 `Authorization`。
- **代理约定**：`POST <endpoint>`，body `{concept, model, prompt}`；响应可为 TemplateSpec、`{spec:...}` 或 chat-completions 风格 `choices[0].message.content`（支持 ```json 包裹）。8 秒超时，失败重试一次；校验两次不过返回 `ai:false` 的 `dsl.draft()` 本地草稿，**不谎称 AI 生成**。
- **输入能力（冻结口径，偿还 #20）**：界面、README、本文件、`docs/02`、`docs/04` 一律写
  「**文字 / 文件名 / 图片内嵌文字**」。`recognize()` 读文字、文件名、SVG `<text>`、PNG `tEXt/iTXt`，
  可选本机 `TextDetector`；**语音只认文件名，请改用文字，或把概念写进文件名**。
  不识别画面内容、不转写语音，**字节不上传**；认不出时 `message` 必非空、不编造概念，
  `level` 标明 supported / fallback / unsupported。对外演示不得宣称能识别图片内容或转写语音。
- **现状（11-08）**：秦已实现 `POST /v1/generate`，接收 `{concept, model, prompt}`，返回 `{spec}`；
  上游完整 Chat Completions URL、密钥与默认模型由服务端 `TTK_LLM_*` 配置。默认仍是本地草稿，
  供应商与模型尚未确定；真实模型调用留给姜联调，不把本机模拟上游验收说成真实模型已接入。
  UI 的 endpoint / model 配置入口与生成模板持久化已由付补齐，详见 7b 节；
  代理覆盖 400 / 429 / 502 / 503 / 504，默认总超时 6500 毫秒、全局每分钟 20 次、同时 2 次，
  不按 IP 计数、不透传上游错误正文；模型响应限 1 MiB，不跟随重定向。公式仍只由客户端 DSL / expr 校验。
  接口细节见 `services/api/openapi.yaml`，配置见 `docs/03` 与 `services/api/README.md`。
  三项缺口见网页偿还 Issue #19 / #20 / #21（旧代号 R1 / R2 / R3），不追认到已关闭的 #I4 / #I5。
  PR #22 只补了能力等级标记与可落盘 `spec`，是前置准备，**不视为 #20 / #21 完成**。
  工坊保存的模板（#I3）与模型生成的模板（#21）现在共用 `ttk.custom.v1` 同一份格式，不再是两条路径。

### 7b. 生成代理设置与模板持久化（付）· `src/ui/settings.js` / `src/ui/app.js`

```js
TTK.settings.readGenConfig()          // -> {endpoint, model}；从 ttk.generator.v1 读，缺省为空
TTK.settings.saveGenConfig(cfg)       // -> 清洗后的 {endpoint, model}；走 TTK.data.write(key, cfg, true)
TTK.app.restoreGeneratorConfig()      // 启动时把配置灌回 TTK.generator.configure()；未配置则零网络请求
TTK.app.generatorConfig()            // -> 当前本机配置（调试用）
TTK.app.saveGenerated(spec)          // -> bool；把 spec 落盘，撞内置 id 返回 false（自身不判 persist）
                                     // 调用方 landGenerated() 只在 mount().persist === true 时才调它
TTK.app.restoreCustom()              // 启动时把 ttk.custom.v1 里的 TemplateSpec 校验编译后挂回引擎（幂等）
TTK.views.exportReport() / importReport(text)  // 报告与工坊共用的同一组导出 / 导入入口
```

- 生成代理设置是**本机设置**，用 `write(..., silent)` 落盘：不进 `events`、不进同步队列、不进
  `exportAll()` 的匿名 JSON、不带任何密钥。前端不接受 `apiKey` / `token`，请求不带 `Authorization`。
- 模型模板（`mount().persist === true`）写入 `TTK.data.saveCustom()`，与工坊共用 `ttk.custom.v1`；
  本地草稿 `persist === false` **不落盘**，页面文案继续如实写「刷新页面后不会保留」。
  `restoreCustom()` 启动时统一走 `dsl.validate` → `dsl.compile` → `engine.register`，已挂载的 id 不重复注册。
- `exportAll()` 的 `customTemplates` 符合 `contracts/learning-trace.schema.json`；`importAll()` 写回后
  由 `importReport()` 立即调 `restoreCustom()` 挂回引擎，不必手动刷新。
- 配置同步服务时 `saveCustom()` 触发 `remote.changed()`，`/trace/import` 的 snapshot 含 `customTemplates`；
  未配置时纯本地、零网络请求。

## 9. 模拟运行时 `TTK.sim`（#I9，曹）· `src/core/engine.js`

静态模板是「一次算完整条曲线」的参数扫描；模拟运行时给 ODE 类沙盒补上跨帧时钟，让曲线随时间揭示。
它随 `engine.js` 一起加载，**不新增 script 标签**（加载顺序不变）。

### 9.1 能力来自模板，不来自引擎

带模拟能力的模板自己声明可选元数据 `tpl.sim`（`RuntimeTemplate` 层的 JS 函数，**不进 TemplateSpec JSON**）：

```js
sim: {
  dt: 0.01,                                     // 固定积分步长，必须与 compute() 里的一致
  unit: 's',                                    // 显示单位，供控制条文案使用
  duration: function (p) { return 14; },        // 总时长，取参数时的快照
  state0:   function (p) { return [θ0, 0]; },   // 初始状态向量
  deriv:    function (t, s, p) { return [...]; },// 右端项 f(t, y)
  marker:   function (t, s) { return { x, y, label, color }; }  // 可选：当前状态标记
}
```

引擎按这个通用形状消费，**不认模板 id、不内置 ODE 映射表**（`contracts/README.md`「三个不许」第 1 条）。
`TTK.math.rk4(f, t, y, dt)` 负责积分；`rk4` 只回传 `(t, y)`，参数快照 `p` 由运行时闭包注入。
目前 `oscillation`（单摆，dt 0.01 / 14s）与 `epidemic`（SIR，dt 0.2 / `p.days` 天）声明了 `sim`。

### 9.2 API

```js
var sim = TTK.sim;                    // 全局单例，随 engine.js 创建
sim.mount(engine)                     // -> id[]，扫描 engine.all() 里的 tpl.sim；app.js 注册模板后调一次
sim.register(id, def) / sim.unregister(id) / sim.registered()   // 运行时装卸任意 ODE 沙盒
sim.supported(id, engine)             // -> bool，是否声明了模拟能力
sim.attach(id, engine)                // -> bool，绑定模板 + 参数快照，计算静态基线并停在第 0 帧
sim.play() / sim.pause() / sim.toggle() / sim.stop()
sim.setSpeed(x)                       // 0.25–8×，越界钳制，非法值返回 false
sim.reset()                           // 回到 t=0，保留 attach 的参数
sim.step(n)                           // 手动推进 n 步（测试与单步调试用）
sim.advance(ms)                       // 按墙钟毫秒推进；暂停时零推进
sim.state()                           // { id, active, playing, speed, t, y, steps, total, dt, progress }
sim.spec()                            // 当前帧，形状就是第 3 节的 ComputeResult
sim.bindControls(els)                 // UI 层注入 { bar, btn, speed, resetBtn, label }
sim.setRenderer(renderer)             // 复用 app.js 的 TTK.Renderer 实例
sim.onDeactivate(fn)                  // 停止 / 切概念时回调，UI 用它重画静态 spec
```

### 9.3 页面装配（`index.html` / `assets/style.css` / `src/ui/app.js`）

控制条在 `index.html` 的 `.canvas-wrap` 里**静态声明**（`#simBar` / `#simPlayBtn` / `#simSpeed` /
`#simResetBtn` / `#simLabel`），`app.js` 在 `init()` 里绑定事件并把 DOM 交给 `bindControls()`。
只有 `sim.supported()` 为真时控制条才显示，切到静态概念自动隐藏并停止；离开沙盒视图自动暂停。

点击「播放模拟」才 `attach()`：之前画面保持完整的静态曲线，视觉零侵入。

### 9.4 帧、事件与副作用

- 每帧把静态 `compute()` 的结果按步数截断：点数等于总步数的序列（时域曲线、包络、相图）逐帧揭示，
  与步数无关的扫描曲线（如 R₀ sweep）原样保留。规则通用，不认模板 id。
- 帧 spec 顶层仍是 `chart / metrics / insight / m`，**字段一个没加**（见第 3 节）。
- **不 emit `change`**：否则 `app.js` 的 change handler 每帧都会记学习轨迹、跑挑战判定，数据就脏了。
  模拟过程中 `engine.revision` / `engine.state` / `TTK.data.trail().length` 都不变。
- `sim` 复用同一个 `Renderer` 画 `canvas#stage`；`stop()` 通过 `onDeactivate` 让 UI 重画静态图，
  避免拖参数 / 切概念后停在最后一帧。
- 时间由 `steps × dt` 反推，长跑不累积浮点误差；暂停不补帧，恢复后状态不漂移。
- 参数 / 概念一变（`select` / `param` / `reset` / `unregister`）自动停止，静态链路照常重算。

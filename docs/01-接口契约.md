# 接口契约（代码级）

> 与 `contracts/` 里的 JSON Schema 配套：JSON Schema 管**数据长什么样**，本文管**函数怎么调**。
> 所有模块都挂在全局 `window.TTK` 下（传统 script 标签，无 ES module、无打包）。

## 0. 全局命名空间与加载顺序

`index.html` 里的脚本顺序就是依赖顺序，新增模块必须按层追加，不能乱序：

```
TTK.math / TTK.Engine       ← src/core/engine.js
TTK.expr                    ← src/core/expr.js       (依赖 TTK.math)
TTK.dsl                     ← src/model/dsl.js       (依赖 TTK.expr)
TTK.generator               ← src/model/generator.js (概念识别与模板生成，依赖 TTK.dsl)
TTK.colors / TTK.Renderer   ← src/viz/render.js
TTK.templates               ← src/model/templates.js (依赖 TTK.colors)
TTK.data                    ← src/learning/data.js
TTK.createGraph             ← src/learning/graph.js  (依赖 engine + data 实例)
TTK.views                   ← src/ui/views.js        (四视图路由)
TTK.engine / UI             ← src/ui/app.js
```

## 1. 引擎（曹）· `src/core/engine.js`

```js
var engine = TTK.createEngine();          // 也可用 new TTK.Engine()
engine.register(runtimeTemplate);         // 必填 id/name/subject/params/compute，id 重复会抛错
engine.all(); engine.get(id); engine.unregister(id); engine.subjects();
engine.defaults(tpl)                     // -> { key: default, ... }
engine.select(id)                        // -> bool，重置参数为默认值并 recompute
engine.setParam(key, rawValue)           // -> bool，自动 clamp / 按 step 取整；无变化返回 false
engine.reset(); engine.recompute();
engine.findByQuery(text)                 // 关键词兜底；TTK.generator.recognize() 会包装它并标注来源
```

**事件**（`engine.on(evt, fn)`）：

| 事件 | payload |
|---|---|
| `change` | `state` — 任何重算后都触发，UI 唯一的数据源 |
| `select` | `state` — 切换概念 |
| `param` | `{ key, value, state }` |
| `reset` | `state` |

`state = { tpl, params, spec, revision, at }`，`spec` 即第 3 节的 `ComputeResult`。

**数学工具** `TTK.math`：`clamp / linspace / rng(seed) / gaussian(rand) / solve(A,b) / rk4(f,t,y,dt) / fmt(v,digits)`。
`rng` 是**可复现**的：拖参数时曲线不得随机抖动，模板里禁止直接用 `Math.random()`。

## 2. RuntimeTemplate（姜与曹的交界）

引擎只认这一个对象形状，DSL 编译产物与手写精修模板**必须统一**：

```js
{
  id, name, subject,                       // 必填
  icon, level, keywords, brief, concept,   // 可选：展示用
  prerequisites: ['gradient', ...],       // 可选：图谱边，填不存在 id 会被忽略
  custom: true, spec: { /* 原始 TemplateSpec */ },  // 可选：DSL 生成模板带
  params: [{ key, label, min, max, step, default, unit, hint }],
  compute: function (p, M) { return ComputeResult; },  // p=参数快照，M=TTK.math
  challenges: [{ text, check: function (p, m) { return boolean; } }]
}
```

`compute` 必须是**纯函数**：同样的 `p` 必须得到同样的结果，不碰 DOM / Canvas / localStorage / 网络。

## 3. ComputeResult（→ 付渲染）

```js
{
  chart: {
    panels: [{
      title, xLabel, yLabel,
      xDomain: [min, max], yDomain: [min, max],     // 可省，渲染器自动推断
      series: [{ name, color, points: [[x, y], ...], style: 'line|dashed|area|scatter|bar', width, fill }],
      markers: [{ x, y, label, color }],            // 可省
      guides:  [{ axis: 'x'|'y', value, label, color }],
      bands:   [{ axis: 'x'|'y', from, to, color, label }]
    }]
  },
  metrics: [{ label, value, unit, digits, tone: 'good|warn|bad|plain', hint }],
  insight: '当前参数下的一句话洞察',
  m: { /* 任意中间量，供 challenges.check 与诊断使用 */ }
}
```

- `chart.panels` 可省（等价单面板）；点多面板由 `TTK.Renderer` 统一布局。
- `points` 里出现 `NaN / Infinity / null` 的坐标会被渲染器跳过，但 **CI 会判为失败**，模板方要保证数值稳定。
- `metrics[].value` 必须是有限数；`tone` 只影响配色，不影响逻辑。
- `m` 是模板与 `check()` 的私有通道，指标卡通过 `metrics` 展示，**不要把展示文案塞进 m**。

渲染侧只有一个入口：`new TTK.Renderer(canvasEl).draw(spec.chart)`。新增概念不应修改渲染器。

## 4. 模板 DSL（姜产出 → 曹编译）· `src/model/dsl.js`

```js
TTK.dsl.validate(spec, existingIds)  // -> { ok, errors[], fns, samples }
TTK.dsl.compile(spec, v?)            // -> RuntimeTemplate，可直接 engine.register()
TTK.dsl.prompt(conceptText)          // -> 给 LLM 的系统提示，要求只输出 TemplateSpec JSON
TTK.dsl.draft(text)                  // -> 本地降级草稿（不假装是 AI 生成）
TTK.dsl.blank() / TTK.dsl.example    // 模板工坊的初始内容
```

公式字符串由 `src/core/expr.js` 求值：`TTK.expr.validate(src) / eval(src, scope) / scope(p, M)`。
作用域只暴露 `x`（横轴）、`p.<key>`（参数）、`m.v0..v4`（指标）、`M`（TTK.math）、`Math`（白名单函数）、`PI / E`。

> ✅ **#I8 已收紧（PR #16）**：标识符路径只允许「根 + 一层属性」，`Math` / `M` 成员走固定函数白名单，
> 参数对象上的方法不可调用；作用域不暴露宿主 `Math`，属性读取只认自有属性，原型链不可达。
> 编译期拒绝除零、字面量/常量折叠溢出、深嵌套、超长表达式与白名单外标识符；运行时结果非有限则抛错。
> 幂右结合、一元负号优先级低于幂（`-2^2 = -4`）。安全断言见 `tools/verify.js` 第 8b 节。

**禁止**：赋值、语句、字符串、下标、对象字面量、函数定义、任何全局访问（含 `window`、`constructor`、`__proto__`）。校验在编译前完成，运行时不执行 JS。

## 5. 数据层（秦）· `src/learning/data.js`

所有读写必须经过 `TTK.data`，**上层不许直接碰 localStorage**：

```js
TTK.data.trail() / progress() / stuck() / custom() / saveCustom(list)
TTK.data.log(event)           // 写事件的唯一入口：补全字段 → 截断 300 → 落盘 → remote.push
TTK.data.markChallenge(id, i) // -> bool，首次完成 true，重复 false
TTK.data.addStuck(id)         // -> 当前卡点条数（上限 200）
TTK.data.byTpl(id, tpl)       // -> { interactions, stuck, challengeDone, challengeTotal, challengeRate }
TTK.data.stats(engine)        // -> 学习报告聚合
TTK.data.timeline(n)          // -> 最近 n 条（倒序）
TTK.data.exportAll(engine)    // -> LearningTrace JSON 字符串（匿名）
TTK.data.importAll(text)      // -> { ok, events } | { ok:false, error }
TTK.data.subscribe(fn) / clear()
TTK.data.migrate()            // -> { sources, normalized, kept }，幂等；模块加载时自动跑一次
TTK.data.lastMigration        // 首次自动迁移的报告，便于排查旧数据
TTK.data.remote.configure(url) // url 为空 => 本地模式；非空 => REST 模式
TTK.data.remote.push(event)    // 离线排队，联网批量 POST 到 <url>/events
TTK.data.remote.flush()        // -> Promise<{ok, events?, error?}>；上传后读回 /trace
TTK.data.remote.pending()      // 待上传事件数（不含进度 / 模板快照）
TTK.data.remote.identity()     // -> 本机随机匿名 ID，16 位十六进制
TTK.data.remote.identity(id)   // -> {ok, anonId? , error?}；手动恢复，缓存与队列按身份隔离
TTK.data.remote.lastError      // 最近一次同步失败原因；4xx 不丢弃队列
TTK.data.remote.storageError   // 非空表示持久化不可用，只能保留本次会话数据
```

**换后端只需替换适配器**：`services/api/openapi.yaml` 定义了 `/events`、`/trace` 等端点；字段名与 `contracts/learning-trace.schema.json` 一致。上层（图谱 / 报告 / 工坊）一行都不用改。

**REST 模式仍同步读取本地缓存**，不把 getter 改成 Promise。`configure(url)` 后后台执行
`/events` 批量上传 → `/trace/import` 合并进度 / 卡点 / 自定义模板 → `GET /trace` 更新缓存，
缓存更新会触发 `subscribe(fn)`；需要即时重绘的视图可消费该通知。手动 `flush()` 可等待本轮同步。
无实时推送 / 定时轮询；在另一台设备操作后，通过 `flush()` 或刷新页面拉取。

待上传队列按服务地址与匿名 ID 分开落盘，不因刷新或 HTTP 错误而丢弃。5xx / 429 / 408 / 网络异常
按 1–30 秒退避重试，恢复联网立即重试；其他 4xx 保留数据并通过 `lastError` 报告，修复后手动 `flush()`。
挑战完成值取 OR，事件和卡点去重；同 id 模板以最后一次成功上传为准，不提供远端删除。
`clear()` 清空本机记录、取消待上传项并关闭同步，远端历史保留；已经送达服务端的请求无法撤回。
未配置 URL 时不建立队列、不生成匿名 ID、不发送网络请求，保持双击运行。

> ✅ **#I13 已完成**：`src/ui/app.js` 不再直接读写本地存储，也不再自带 `save()` / `trail` 内存缓存；
> 轨迹、挑战、卡点全部走 `TTK.data`，卡点推荐走 `graph.recommend()`。
> `TTK.data.migrate()` 在模块加载时幂等接管早期无版本后缀的键，**只写 v1、不删旧键**，旧轨迹不丢失。
> 数据层的 getter 会顺带规范化脏数据，字段与 `learning-trace.schema.json` 保持一致。

## 6. 概念图谱与诊断（付 + 秦）· `src/learning/graph.js`

```js

```

## 7. 四视图路由（付）· `src/ui/views.js`

四视图已由 #I1 接入。`index.html` 里 `#viewNav` 是导航条，`#view-<id>` 是四个容器，同一时刻只有一个不 `hidden`；
沙盒三栏的 DOM 结构保持不变，所以拖参数 / 指标 / 挑战判定的链路完全没动。

```js
TTK.views.routes()            // -> [{ id, name, hash, mount, todo }, ...]，固定 4 条
TTK.views.register(id, fn)    // 注册挂载函数；渲染时只改自己的容器
TTK.views.mount(id)           // -> bool，未知 / 未注册返回 false
TTK.views.go(id, tpl)         // 切视图并写 hash；tpl 可省
TTK.views.setTpl(id)          // 应用层切概念时调用：保留当前视图，只换后半段
TTK.views.start()             // 应用层 init 末尾调一次：绑定 hashchange，返回初始 { view, tpl }
TTK.views.current()           // -> 当前 route 或 null
TTK.views.parseHash()         // -> { view, tpl }
TTK.views.hash()              // -> 当前应有的 hash 字符串
TTK.views.on(fn)              // fn(evt, payload)；'change' 的 payload = { route, tpl, hash }
```

**hash 格式 `#<view>/<tplId>`**（例：`#report/overfit`）：前半段决定视图，后半段记住当前概念；
v0 的 `#overfit` 这类只有模板 id 的链接会兼容回沙盒。`go()` / `setTpl()` 同步应用一次，
并用 `lastApplied` 去重浏览器随后派发的 `hashchange`，不会循环。
隐藏期间 `app.js` 跳过 Canvas 绘制，切回沙盒时由 `change` 事件补一次重绘（渲染器每次重读画布尺寸）。

### 7a. 概念输入与模板生成（姜）· `src/model/generator.js`

```js
TTK.generator.configure({ endpoint, model, transport }) // -> {enabled, endpoint, model}；endpoint 为空 = 本地模式
TTK.generator.config()                                   // -> 公开配置，不含任何密钥
TTK.generator.recognize(input)                           // -> {ok, conceptId, concept, source, unsupported, message}
TTK.generator.generate(concept, { ids })                 // 本地模式：同步返回 {ok, spec, source:'local-draft', ai:false, reason, attempts}
                                                         // 配置代理：返回 Promise，成功 {ai:true, source:'llm', spec}
TTK.generator.mount(engine, spec)                        // -> {ok, tpl, source} | {ok:false, errors[]}；唯一进引擎的入口
```

- **安全**：模型输出永远只当数据。先 JSON 化去函数，再 `dsl.validate` → `dsl.compile`（公式只走 `expr` 白名单）→ `engine.register`；`apiKey` / `token` 字段一律不接受，客户端不带 `Authorization`。
- **代理约定**：`POST <endpoint>`，body `{concept, model, prompt}`；响应可为 TemplateSpec、`{spec:...}` 或 chat-completions 风格 `choices[0].message.content`（支持 ```json 包裹）。8 秒超时，失败重试一次；校验两次不过返回 `ai:false` 的 `dsl.draft()` 本地草稿，**不谎称 AI 生成**。
- **输入能力**：`recognize()` 读文字、文件名、SVG `<text>`、PNG `tEXt/iTXt`，可选本机 `TextDetector`；**字节不上传**。语音目前只按文件名匹配，认不出时 `message` 必非空、不编造概念。
- **现状（11-08）**：`services/api/` 里还没有 `/generate` 实现，UI 也没有 endpoint 配置入口，所以默认链路是
  `recognize → 本地草稿 → mount`；生成模板只在内存里，刷新不保留。三项缺口分别见偿还 Issue R1 / R2 / R3，
  不追认到已关闭的 #I4 / #I5。

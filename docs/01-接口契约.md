# 接口契约（代码级）

> 与 `contracts/` 里的 JSON Schema 配套：JSON Schema 管**数据长什么样**，本文管**函数怎么调**。
> 所有模块都挂在全局 `window.TTK` 下（传统 script 标签，无 ES module、无打包）。

## 0. 全局命名空间与加载顺序

`index.html` 里的脚本顺序就是依赖顺序，新增模块必须按层追加，不能乱序：

```
TTK.math / TTK.Engine       ← src/core/engine.js
TTK.expr                    ← src/core/expr.js       (依赖 TTK.math)
TTK.dsl                     ← src/model/dsl.js       (依赖 TTK.expr)
TTK.generator               ← src/model/generator.js (骨架，依赖 TTK.dsl)
TTK.colors / TTK.Renderer   ← src/viz/render.js
TTK.templates               ← src/model/templates.js (依赖 TTK.colors)
TTK.data                    ← src/learning/data.js
TTK.createGraph             ← src/learning/graph.js  (依赖 engine + data 实例)
TTK.views                   ← src/ui/views.js        (骨架)
TTK.engine / UI             ← src/ui/app.js
```

## 1. 引擎（队员 B）· `src/core/engine.js`

```js
var engine = TTK.createEngine();          // 也可用 new TTK.Engine()
engine.register(runtimeTemplate);         // 必填 id/name/subject/params/compute，id 重复会抛错
engine.all(); engine.get(id); engine.unregister(id); engine.subjects();
engine.defaults(tpl)                     // -> { key: default, ... }
engine.select(id)                        // -> bool，重置参数为默认值并 recompute
engine.setParam(key, rawValue)           // -> bool，自动 clamp / 按 step 取整；无变化返回 false
engine.reset(); engine.recompute();
engine.findByQuery(text)                 // 关键词匹配降级实现，A 接好多模态后可替换
```

**事件**（`engine.on(evt, fn)`）：

| 事件 | payload |
|---|---|
| `change` | `state` — 任何重算后都触发，UI 唯一的数据源 |
| `select` | `state` — 切换概念 |
| `param` | `{ key, value, state }` |
| `reset` | `state` |

`state = { tpl, params, spec, revision, at }`，`spec` 即第 3 节的 `ComputeResult`。

**数学工具** `TTK.math`：`clamp / linspace / rng(seed) / gaussian(rand) / solve(A,b) / rk4(f,t,y,dt) / fmt(v,digits)`。
`rng` 是**可复现**的：拖参数时曲线不得随机抖动，模板里禁止直接用 `Math.random()`。

## 2. RuntimeTemplate（队员 A / B 的交界）

引擎只认这一个对象形状，DSL 编译产物与手写精修模板**必须统一**：

```js
{
  id, name, subject,                       // 必填
  icon, level, keywords, brief, concept,   // 可选：展示用
  prerequisites: ['gradient', ...],       // 可选：图谱边，填不存在 id 会被忽略
  custom: true, spec: { /* 原始 TemplateSpec */ },  // 可选：DSL 生成模板带
  params: [{ key, label, min, max, step, default, unit, hint }],
  compute: function (p, M) { return ComputeResult; },  // p=参数快照，M=TTK.math
  challenges: [{ text, check: function (p, m) { return boolean; } }]
}
```

`compute` 必须是**纯函数**：同样的 `p` 必须得到同样的结果，不碰 DOM / Canvas / localStorage / 网络。

## 3. ComputeResult（→ 队长渲染）

```js
{
  chart: {
    panels: [{
      title, xLabel, yLabel,
      xDomain: [min, max], yDomain: [min, max],     // 可省，渲染器自动推断
      series: [{ name, color, points: [[x, y], ...], style: 'line|dashed|area|scatter|bar', width, fill }],
      markers: [{ x, y, label, color }],            // 可省
      guides:  [{ axis: 'x'|'y', value, label, color }],
      bands:   [{ axis: 'x'|'y', from, to, color, label }]
    }]
  },
  metrics: [{ label, value, unit, digits, tone: 'good|warn|bad|plain', hint }],
  insight: '当前参数下的一句话洞察',
  m: { /* 任意中间量，供 challenges.check 与诊断使用 */ }
}
```

- `chart.panels` 可省（等价单面板）；点多面板由 `TTK.Renderer` 统一布局。
- `points` 里出现 `NaN / Infinity / null` 的坐标会被渲染器跳过，但 **CI 会判为失败**，模板方要保证数值稳定。
- `metrics[].value` 必须是有限数；`tone` 只影响配色，不影响逻辑。
- `m` 是模板与 `check()` 的私有通道，指标卡通过 `metrics` 展示，**不要把展示文案塞进 m**。

渲染侧只有一个入口：`new TTK.Renderer(canvasEl).draw(spec.chart)`。新增概念不应修改渲染器。

## 4. 模板 DSL（队员 A 产出 → 队员 B 编译）· `src/model/dsl.js`

```js
TTK.dsl.validate(spec, existingIds)  // -> { ok, errors[], fns, samples }
TTK.dsl.compile(spec, v?)            // -> RuntimeTemplate，可直接 engine.register()
TTK.dsl.prompt(conceptText)          // -> 给 LLM 的系统提示，要求只输出 TemplateSpec JSON
TTK.dsl.draft(text)                  // -> 本地降级草稿（不假装是 AI 生成）
TTK.dsl.blank() / TTK.dsl.example    // 模板工坊的初始内容
```

公式字符串由 `src/core/expr.js` 求值：`TTK.expr.validate(src) / eval(src, scope) / scope(p, M)`。
作用域只暴露 `x`（横轴）、`p.<key>`（参数）、`m.v0..v4`（指标）、`M`（TTK.math）、`Math`（白名单函数）、`PI / E`。
**禁止**：赋值、语句、字符串、下标、对象字面量、函数定义、任何全局访问（含 `window`、`constructor`、`__proto__`）。校验在编译前完成，运行时不执行 JS。

## 5. 数据层（队员 C）· `src/learning/data.js`

所有读写必须经过 `TTK.data`，**上层不许直接碰 localStorage**：

```js
TTK.data.trail() / progress() / stuck() / custom() / saveCustom(list)
TTK.data.byTpl(id, tpl)       // -> { interactions, stuck, challengeDone, challengeTotal, challengeRate }
TTK.data.stats(engine)        // -> 学习报告聚合
TTK.data.timeline(n)          // -> 最近 n 条（倒序）
TTK.data.exportAll(engine)    // -> LearningTrace JSON 字符串（匿名）
TTK.data.importAll(text)      // -> { ok, events } | { ok:false, error }
TTK.data.subscribe(fn) / clear()
TTK.data.remote.configure(url) // url 为空 => 本地模式；非空 => REST 模式
TTK.data.remote.push(event)    // 离线排队，联网批量 POST 到 <url>/events
```

**换后端只需替换适配器**：`services/api/openapi.yaml` 定义了 `/events`、`/trace` 等端点；字段名与 `contracts/learning-trace.schema.json` 一致。上层（图谱 / 报告 / 工坊）一行都不用改。

> ⚠️ 当前 `src/ui/app.js` 里还留着 v0 自带的本地存储与卡点诊断实现（`save()` / `trail` / `diagnoseStuck()`），
> 与 `TTK.data`、`TTK.createGraph` 是**两套并存**。迁移任务见 `02-路线图与任务看板.md` 的 #I13。

## 6. 概念图谱与诊断（队长 + 队员 C）· `src/learning/graph.js`

```js
var graph = TTK.createGraph(engine, TTK.data);
graph.edges()          // -> [{ from: 先修id, to: 概念id }]
graph.depth(id)        // 先修链深度（防环）
graph.mastery(id)      // 0..1，挑战完成 + 探索深度 + 接触过 - 卡点惩罚
graph.recommend()      // 按推荐分数降序的完整建议列表（闭环出口）：
                       // [{ tpl, mastery, prereqReady, score, reason, stats }, ...]；UI 取前几条展示
graph.layout()         // { nodes:[{id,tpl,depth,x,y,mastery}], edges, nodeW, nodeH, width, height }
```

## 7. 待接入模块的接口占位

骨架已由 `index.html` 加载（零副作用），打开页面即可在控制台调试 `TTK.views` / `TTK.generator`：

| 文件 | 归属 | 已提供 | 需要实现 |
|---|---|---|---|
| `src/ui/views.js` | 队长 | `register(id, fn)` / `mount(id)` / `go(id)` / `current()` / `routes()` / `on()` | 四个视图的挂载函数 + app.js 导航接入（#I1） |
| `src/model/generator.js` | 队员 A | `configure()` / `recognize()` / `generate()` / `mount(engine, spec)` | LLM 生成与输出校验（#I4）、多模态识别（#I5） |

未实现的视图 `mount()` 会明确告警并返回 `false`，绝不假装成功；`generate()` 在没接模型时返回 `ai:false` 的本地草稿。

# 参赛合规（提交前必读）

> 这两条是硬规矩，违反会直接影响参赛资格。所有成员在提交改动前都要过一遍。

## 一、匿名评审

**所有提交材料**（项目计划书、Beta 原型、演示视频、答辩 PPT、界面文案、截图、README、公开仓库）
**不得出现**：校名、院系名、成员真实姓名、指导老师姓名、学号、班级、以及任何可识别出学校或个人的字眼。
队名 **拖拖看** 不含校名，可用。

### 仓库内部的约定（仅私有仓库）

- 为方便四人并行，队内文档、Issue、代码注释**直接用姓名标注分工**：付嘉一 / 姜雅文 / 曹蕾 / 秦庆泽。
- 这是私有仓库内部的便利，**不是对外口径**。姓名会写进 git 历史，所以下面「提交前一次性清理」是必做步骤。
- 技术标识仍用字母代号，避免破坏已建好的标签与分支约定：
  `owner:lead` = 付嘉一，`owner:a` = 姜雅文，`owner:b` = 曹蕾，`owner:c` = 秦庆泽；
  分支前缀同理（`feat/a-xxx`）。
- **GitHub 账号名、git 提交作者名、commit 邮箱**也可能泄露身份：仓库保持**私有**；
  演示录屏前关掉界面上的账号信息；公开前人工检查提交历史与贡献者列表。
- 演示数据必须匿名：`TTK.data.exportAll()` 的 `notice` 字段已声明不含姓名/学校/设备标识；
  后端（`services/api/`）**不许记录 IP、设备指纹、真实姓名**。

### 提交前一次性清理（由付嘉一执行）

以下场景之前必做：初赛 / 复赛提交材料、项目计划书、Beta 演示包、演示录屏、答辩 PPT、
对外分享的截图、把仓库转为公开、把代码打包发给评委 / 第三方。

1. 列出全部待清理位置（**含本文件自身**）：

   ```bash
   git grep -n -E '付嘉一|姜雅文|曹蕾|秦庆泽'
   ```

2. 把命中位置统一改回 `队长 / 队员 A / 队员 B / 队员 C` 或直接删除；`owner:*` 标签与分支名不用改。
3. 把四个姓名**临时**写入 `.local/forbidden.txt`（一行一个，该目录不入库），跑 `npm run check:anon`：
   扫描会把残留位置全部列出并判红，改到干净后再清空词表（日常开发不要留着，否则每次 check 都红）。
4. **处理 git 历史**：提交包导出一份清理后的干净快照即可；若要把仓库公开或发给第三方，
   还需由付嘉一单独重写历史（filter-repo / 全新仓库导入），并确认 `git log` 与贡献者列表无可识别信息。
5. 演示录屏、答辩 PPT、界面文案单独人工复核，别把仓库里的姓名带进去。

### 匿名检查工具

```bash
npm run check:anon
```

脚本扫描被 git 跟踪的文本文件，拦截邮箱、手机号、身份证号等模式，以及 `.local/forbidden.txt`
里的本机敏感词。工具自身不含任何真实姓名，所以敏感词表只能在各自电脑本地维护。

> CI 里没有这份词表，只做模式检查；**人工复核不能省**。

## 二、原创性

- 作品须原创，核心工作必须在**本次大赛期间**完成。
- 不得使用已参加过其他国家级公开比赛的作品参赛。
- 复用已有积累（如已有的小游戏平台引擎）要在项目计划书里如实说明边界，并保留本次新增工作的可追溯记录（git 历史即证据）。
- 引入任何第三方库 / 模型 / 素材，都要在提交说明和 `docs/` 里记录来源与许可；当前 v0 原型 **零第三方依赖**。
- 生成式内容（AI 生成的模板、文案）需注明工具与人工审核过程，不得把模型输出直接当原创设计全盘提交。

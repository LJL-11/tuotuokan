# 参赛合规（提交前必读）

> 这两条是硬规矩，违反会直接影响参赛资格。所有成员在提交改动前都要过一遍。

## 一、匿名评审

**所有提交材料**（项目计划书、Beta 原型、演示视频、答辩 PPT、界面文案、截图、README、公开仓库）
**不得出现**：校名、院系名、成员真实姓名（全名）、指导老师姓名、学号、班级、
以及任何可识别出学校或个人的字眼。队名 **拖拖看** 不含校名，可用。

### 本仓库已公开

`LJL-11/tuotuokan` 为 **public** 仓库，因此**仓库里的每一行都等同于对外材料**：
README、docs、代码注释、schema 描述、Issue、PR、commit message、git 历史、贡献者列表，全部算。

- 分工一律用**姓氏单字或代号**：付 / 姜 / 曹 / 秦，或 `队长 / 队员 A / 队员 B / 队员 C`。
  **禁止写任何成员全名。**
- 技术标识保持字母代号，避免破坏已建好的标签与分支约定：
  `owner:lead` = 付，`owner:a` = 姜，`owner:b` = 曹，`owner:c` = 秦；分支前缀同理（`feat/a-xxx`）。
- **GitHub 账号名、git 提交作者名、commit 邮箱**仍可能泄露身份：
  提交身份由队长统一约定，不要在单次提交里临时覆盖；演示录屏前关掉界面上的账号信息；
  公开前人工检查提交历史与贡献者列表。账号名如需彻底匿名，须换用组织账号。
- 仓库自带的 Pages 地址（<https://ljl-11.github.io/tuotuokan/>）是公开仓库的固定地址，不含成员姓名 / 校名，
  可写进部署说明；但它会带出账号名，**演示录屏与初赛提交包不要附仓库 / Pages 链接**，
  改用单独导出的干净快照与本地演示。
- 演示数据必须匿名：`TTK.data.exportAll()` 的 `notice` 字段已声明不含姓名/学校/设备标识；
  后端（`services/api/`）**不许记录 IP、设备指纹、真实姓名**。

### 本地敏感词表（建议常驻）

`tools/check-anonymity.js` 只扫被 git 跟踪的文本文件，拦截邮箱、手机号、身份证号等模式，
以及 `.local/forbidden.txt` 里的本机敏感词（该目录不入库）。

由于仓库已公开、日常禁止出现全名，**建议每位成员把四位成员全名、校名、指导老师姓名
一行一个写进自己电脑的 `.local/forbidden.txt` 并常驻**，`npm run check` 会在本地直接拦下
手滑写回全名的情况。工具与仓库本身都不含任何全名，词表只能在各自电脑本地维护。

> CI 里没有这份词表，只做模式检查；**人工复核不能省**。

```bash
npm run check:anon   # 匿名合规扫描
npm run check        # 两项一起跑
```

### 残留风险：git 历史与账号名

改文件只能清掉**当前版本**。早期两个提交里曾写入过全名与真实邮箱，
公开仓库的历史 diff、贡献者列表、网页上历史 Issue 正文可能仍可检索到；
这些无法靠提交新版本消除，只能由队长重写历史（filter-repo / 全新仓库导入）并 force push，
且应在成员开始大量提交前完成。**初赛提交材料里不要附本仓库链接**，只附单独导出的干净快照。

## 二、原创性

- 作品须原创，核心工作必须在**本次大赛期间**完成。
- 不得使用已参加过其他国家级公开比赛的作品参赛。
- 复用已有积累（如已有的小游戏平台引擎）要在项目计划书里如实说明边界，并保留本次新增工作的可追溯记录（git 历史即证据）。
- 引入任何第三方库 / 模型 / 素材，都要在提交说明和 `docs/` 里记录来源与许可；当前 v0 原型 **零第三方依赖**。
- 生成式内容（AI 生成的模板、文案）需注明工具与人工审核过程，不得把模型输出直接当原创设计全盘提交。

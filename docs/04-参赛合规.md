# 参赛合规（提交前必读）

> 这两条是硬规矩，违反会直接影响参赛资格。所有成员在提 PR 时都要过一遍。

## 一、匿名评审

**所有提交材料**（项目计划书、Beta 原型、演示视频、答辩 PPT、界面文案、截图、README、公开仓库）
**不得出现**：校名、院系名、成员真实姓名、指导老师姓名、学号、班级、以及任何可识别出学校或个人的字眼。
队名 **拖拖看** 不含校名，可用。

因此在仓库里：

- 队员统一用代号 **队长 / 队员 A / 队员 B / 队员 C**，确认本名后也**不要写进仓库文件**。
- `docs/`、Issue、PR 描述里同样只用代号。
- **GitHub 账号名、git 提交作者名、commit 邮箱**也可能泄露身份：
  - 仓库建议设为**私有**；
  - 演示录屏前先把界面上的账号信息关掉；
  - 若要公开仓库，先跑 `npm run check:anon` 并人工检查提交历史与贡献者列表。
- 演示数据必须是匿名的：`TTK.data.exportAll()` 的 `notice` 字段已声明不含姓名/学校/设备标识，
  后端（`services/api/`）**不许记录 IP、设备指纹、真实姓名**。

### 匿名检查工具

```bash
npm run check:anon
```

脚本会扫描被 git 跟踪的文本文件，拦截邮箱、手机号、身份证号等模式，以及**本机自定义敏感词表**：
把校名、成员姓名、指导老师姓名等一行一个写进 `.local/forbidden.txt`（该目录已被 `.gitignore` 排除，不会入库）。
工具本身不含任何真实姓名，所以敏感词表只能在各自电脑本地维护。

> CI 里没有这份词表，因此只做模式检查；**人工复核不能省**。

## 二、原创性

- 作品须原创，核心工作必须在**本次大赛期间**完成。
- 不得使用已参加过其他国家级公开比赛的作品参赛。
- 复用已有积累（如已有的小游戏平台引擎）要在项目计划书里如实说明边界，并保留本次新增工作的可追溯记录（git 历史即证据）。
- 引入任何第三方库 / 模型 / 素材，都要在 PR 描述和 `docs/` 里记录来源与许可；当前 v0 原型 **零第三方依赖**。
- 生成式内容（AI 生成的模板、文案）需注明工具与人工审核过程，不得把模型输出直接当原创设计全盘提交。
